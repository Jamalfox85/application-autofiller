# Workday manual dry-run

Engineering checklist for the three live-tenant prove-outs. This is not a success-rate report. A pass is what a person sees on the form before Submit.

Postings below were checked **2026-09-29 ET** (`isExternal` / `postingAvailable` true). Re-open each URL before the run. If the posting is closed, or the only path is SSO with no "Sign in with email" / "Create Account", stop and pick another external posting. Do not use a password-manager or company SSO.

These are external job URLs on `*.myworkdayjobs.com` (Cisco and Zillow on `wd5`, Salesforce on `wd12`). The apply chooser opens from **Apply** on that page, then **Apply Manually**. Host families `*.myworkday.com` and `*.myworkdaysite.com` are covered by unit tests.

**Cisco inspection (2026-09-29, no account created, no application submitted).** Apply opens a modal (Autofill with Resume / Apply Manually / Use My Last Application). Apply Manually goes straight to Create Account: there is no Sign-in-with-email step. The form has `email`, `password`, and `verifyPassword`. `createAccountCheckbox` and `click_filter` are absent. The account control is `createAccountSubmitButton`. No captcha, SSO, or geo wall through that boundary. The extension skips a missing sign-in button, clicks the agreement checkbox only when it is present, and prefers `createAccountSubmitButton` over a card-local `click_filter`. It still does not click application Submit.

**Cisco My Information (2026-09-30, account created, no application submitted).** Apply Manually URL: `.../Software-Engineering-Technical-Leader---Cisco-IQ_2019787/apply/applyManually`. Create Account succeeded. My Information then filled names, address line, city, postal code, email, and phone number, and stopped on validation before Experience.

- **Country.** The profile value is the slug `united_states`. The closed control showed Georgia (the country), and the extension logged `Country option not found for: united_states`. The matcher now treats that slug as United States and chooses the option "United States of America" when both Georgia and the United States are in the list. It does not click Georgia for a US profile. State slugs such as `New_York` follow the same rule.
- **Phone Device Type.** Required, left empty, with `Mobile phone type option not found`. The prompt button may be `phone-device-type` or `phoneType`, and the rows are `promptOption` labels (Mobile, Landline, Fax), not only `[role="option"]`. There is no device-type field on the profile. The fill still selects Mobile or Cell, which is the existing default, and does not fall back to Landline or Fax.
- **How Did You Hear About Us?** and **Former Cisco employee / email ID** (Yes/No). On that run both stayed empty and blocked Next, because the vault has no source answer and no former-employee answer. They are no longer left blank. A required Yes/No (former employee, previous employee, or "have you worked here") is answered **No**. It is not answered Yes. The source question is a dropdown: choose a listed option, preferring Other, then Company website, then Career site, then that site's own careers page (for example "Cisco Careers"). If none of those labels are on the control, another listed option is used so the required question is not blank. The value has to be one of the options. Yes and employee referral are not selected. LinkedIn, Indeed, or Job Board are used only when no neutral option is listed.

**Cisco My Experience (2026-10-04, no application submitted).** My Information passed: country United States of America, phone device type Mobile, How Did You Hear About Us Cisco Jobs Career Site, former employee No. Work experience filled. Education stopped Save and Continue. GPA 3.8 was filled. School or University is a prompt: opening it shows a Search box and "No Items." until that search box receives the query. The closed field is not the catalog input, and a typed query is not a selected school. The fill types the profile school into that search box and clicks the matching prompt row when one appears. The committed value is the selected pill. If the catalog has no matching row, the search is cleared and school stays blank. Degree opens to Select One, Doctor of Medicine (MD), Associate of Science, Bachelor of Science, Doctor of Medicine, and Juris Doctorate. "No Items." and Select One are not selections. The fill clicks the Bachelor of Science row itself. Associate of Science and Bachelor of Arts are not selected for a Bachelor of Science profile. A listed "Bachelor's Degree" or "Bachelors" is still used when that is the label and Bachelor of Science is not on the menu. Experience location is still omitted when the profile has no city or state. Submit is not clicked.

## Do not

- Do not click **Submit**, **Submit Application**, or **Send**.
- You may click **Apply**, **Apply Manually**, **Next**, or **Save and Continue** to reach later steps. Stop on the review step.
- Create Account is not application submit. To prove the missing-login path, leave Application Accounts empty and confirm the notice instead of creating a candidate account.

## Profile to load

- Contact: first name, last name, email, phone, address, city, state (abbreviation is fine), postal code, country.
- One current experience (`present`, no end date) and one past experience (end date `YYYY-MM`).
- One education row: school, degree, field of study, start year, graduation year.
- Optional: EEO on, with disability status `yes` / `no` / `decline`.
- Resume: the profile mirror still shows a filename. The file bytes are the object in the private Supabase Storage bucket `resumes`, at `profiles.resume_file_path`. A filename with no object is left empty.
- Work authorization stays empty. "How did you hear about us" and former-employee / previous-employee Yes/No are not vault fields. The Yes/No is answered No. The source dropdown is a listed option: Other, Company website, Career site, or that site's careers page when one of those is on the control.

## Steps

1. Open the job URL. The extension clicks the **Apply** button whose label is Apply, then **Apply Manually**. If those controls are not clicked, click them yourself. Do not click **Autofill with Resume**, **Use My Last Application**, or **Submit**. If auto-detect is on, let fill run; otherwise trigger fill once.
2. **Account.** On Cisco, Apply Manually opens Create Account immediately (no Sign-in-with-email, no agreement checkbox, no `click_filter`). Salesforce uses the same three fields inside `formField-*` wrappers and may offer `signInLink` instead of Sign-in-with-email. If Create Account redirects to `/login`, Salesforce and Zillow share that page: email and password, no visible verify-password field. The sign-in password is the Workday Application Accounts password. A hidden decoy, and a hidden create-account block that still has verify-password, are not the fields that fill. Sign In is left for you to click. Zillow's Create Account uses Cisco's bare `email`, `password`, and `verifyPassword` ids, shows `createAccountCheckbox`, and has no `createAccountSubmitButton`; its account control is `click_filter`. Zillow also shows `signInLink` and `utilityButtonSignIn`. Those sign-in controls are not followed once Create Account or `/login` is showing. With no Workday login saved: the Application Accounts notice appears, email/password stay empty, and the account control is not clicked. With a login saved: email, password, and verify password fill on Create Account; an agreement checkbox is clicked only when the tenant renders one; the click target is `createAccountSubmitButton` when that button exists, otherwise a `click_filter` inside the account card. A page-level Next control is not the account submit. This click creates the candidate account. It is not application Submit. `/login` fills email and password and does not click Sign In.
3. **My Information.** First and last name, address line 1, city, postal code, phone, and email match the profile. Address line 2 fills only when the profile has one. Middle name stays blank. Country and state show a **selected** option (a full state name when the profile has an abbreviation or slug such as `New_York`). A profile country of `united_states` selects the United States option, for example "United States of America", including when Georgia is also in the country list. Phone device type is Mobile or Cell, selected from the list. The profile has no device-type field; Landline and Fax are not substitutes.
4. **Source / how did you hear, and former employee.** A former-employee, previous-employee, or "have you worked here" Yes/No shows **No**. It does not show Yes. How did you hear shows a selected option from that dropdown. Prefer Other, then Company website, then Career site, then the site's own careers page. The selected label is one that exists on the control. Yes and employee referral are not chosen.
5. **Resume.** A plain Resume, Upload, or Choose file input receives the stored resume object. Autofill with Resume and Use My Last Application are not clicked. A cover-letter file input stays empty. If the profile has a filename and no storage object, the resume input stays empty.
6. **My Experience.** A work-experience row is added for each profile role: job title, company, location only when city or state exists, start month and year in the date parts. Current role checks "I currently work here" and does not invent an end date. Past role fills the end date. Education adds a row: school and field of study are chosen from the suggestion list when one matches; degree is a selected list option, not only typed text; GPA and years fill when present. A tenant that shows only one of the two sections still fills that section.
7. **Work authorization and other custom questions.** Untouched. Source and former-employee questions are step 4.
8. **EEO.** With EEO answers off, disability, signature name, and signature date stay empty. With EEO on, the disability choice matches the label (not a checkbox picked only by position), and the self-id name and today's date fill.
9. Stop before Submit. The page should not keep opening and closing the same dropdown.

## Pass

- Supported fields above are filled correctly.
- Dropdowns show a selected option.
- Nothing landed in the wrong field.
- The page did not hang.
- Submit was not clicked.
